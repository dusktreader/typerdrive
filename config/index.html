Typerdrive configuration

Typerdrive uses its own config for app identity and the behavior of its built-in features.

Overview

When you build an app with Typerdrive, there are two kinds of configuration to keep straight.

The settings feature is for values that your app uses to control its behavior outside of what typerdrive provides out of the box. When you build an app on top of typerdrive, you might need your app to remember the user's home planet. In that case, you will use the builtin settings feature to remember the planet name. Typerdrive knows about log files and storage, but it doesn't know anything about planets; that's part of your app's logic.

TyperdriveConfig, on the other hand, is used internal Typerdrive logic and builtin features. The config controls some Typerdrive behavior. None of the config settings are required, but you might find it useful to bind some configuration values.

With TyperdriveConfig, you can explicitly provide an app name, a version number, and a description that will be shown when you use the info command to show the app info. You can also control things like log rotation, state and cache home directories, and default console display behavior. All of these use sensible defaults, so you may never need to use them. If you do, read the info below to learn more.

Usage

Set configuration

set_typerdrive_config() is usually called during app setup, before Typer invokes the CLI. It accepts keyword arguments for the values the app wants to override.

import typer
from typerdrive import add_info_subcommand, set_typerdrive_config

set_typerdrive_config(
    app_name="config-example",
    version="1.2.3",
    description="Demonstrate Typerdrive configuration.",
    log_file_name="config-example.log",
    console_ascii_only=True,
    console_width=100,
    state_home="/tmp/typerdrive-docs-state",
    cache_home="/tmp/typerdrive-docs-cache",
)

cli = typer.Typer()
add_info_subcommand(cli)


if __name__ == "__main__":
    cli()

The example sets app metadata and logging/output options before creating the CLI. The config stays in memory for the current process; it does not write or replace the app's settings file.

Inspect configuration

add_info_subcommand() adds the info and version commands to a Typer app. info shows app metadata; info --full shows every config value and computed storage path. version prints <app_name> v<version> by default, or <app_name> (version unknown) if no version is configured. version --terse prints only the version string, or unknown when no version is configured.

When we run the info example, we see the compact app info:

$ python examples/config/info.py info

|                                                                                                  |
| Name         config-example                                                                      |
| Version      1.2.3                                                                               |
| Description  Demonstrate Typerdrive configuration.                                               |

+--------------------------------------------------------------------------------------------------+

Show the app version

We can show the app's version info with the version command:

$ python examples/config/info.py version
config-example v1.2.3

The terse version command prints just the version:

$ python examples/config/info.py version --terse
1.2.3

Details

Configuration values

app_name defaults to the executable name derived from sys.argv[0]. version and description default to None.

Value Default Purpose
app_name sys.argv[0] Identifies the client app and scopes its Typerdrive data.
version None Client app version displayed by info and version.
description None Short client app description displayed by info.
log_file_rotation 1 week Loguru rotation policy for log files.
log_file_retention 1 month Loguru retention policy for log files.
log_file_compression tar.gz Compression format for rotated logs.
log_file_name app.log Name of the managed log file.
console_width None Fixed Rich console width; None uses the terminal width.
console_ascii_only False Use ASCII borders instead of Unicode borders in Typerdrive output.
state_home XDG_STATE_HOME Base directory for state files and logs.
cache_home XDG_CACHE_HOME Base directory for cache data.

Computed storage paths

Typerdrive computes storage paths from app_name, state_home, and cache_home:

Value Path
log_dir <state_home>/<app_name>/logs
settings_path <state_home>/<app_name>/settings.json
files_dir <state_home>/<app_name>/files
database_path <state_home>/<app_name>/db.sqlite
app_cache_home <cache_home>/<app_name>
managed_cache_dir <cache_home>/<app_name>/managed

By default, state_home uses XDG_STATE_HOME (usually ~/.local/state) and cache_home uses XDG_CACHE_HOME (usually ~/.cache). Setting either field overrides its corresponding XDG directory. The settings_path is where Typerdrive stores the app settings feature; it is not a replacement for the app's own settings model.
